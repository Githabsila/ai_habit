# Копии базы и как поднять ADAM заново

Здесь всё, что нужно, если пропал том на Railway, сломался сервер или нужно переехать на другой хостинг.
Секретов в этом файле нет: ключи у владельца (менеджер паролей) и в переменных Railway.

## Где лежат копии

| Где | Как часто | Сколько хранится | Переживёт потерю тома на Railway |
|---|---|---|---|
| На томе Railway, папка `backups/` | при каждом запуске бота и раз в сутки | 5 последних + по одной за каждый из 14 последних дней | нет, лежат рядом с базой |
| **В Telegram у администратора** (`ADMIN_ID`), файл `….db.gz` | **раз в сутки в 05:00 UTC** и через 2 минуты после запуска, если за 20 часов не уходила | вся история чата, пока её не удалят | **да** |
| Код: GitHub `Githabsila/ai_habit` | при каждом пуше | вся история | да (но базы там нет) |

Файл в Telegram приходит без звука, с подписью «Копия базы · дата · размер · целостность проверена». Если за сутки
файла нет, смотри в ежедневную сводку админа: ошибки копии (`backup_*`) попадают в журнал ошибок. Если база стала больше
50 МБ после сжатия, бот сам напишет об этом: тогда нужно внешнее хранилище.

Важно: копия содержит данные всех людей (Telegram ID, привычки). Хранить её нужно там, куда не пускают посторонних, а чат
с ботом на телефоне должен быть защищён кодом.

## 1. Проверить копию (ничего не меняет)

Скачай файл из Telegram и выполни на компьютере с Python 3.9+ в папке проекта:

```bash
python backups/restore.py путь/к/копия.db.gz --check
```

Скрипт распакует файл рядом, проверит целостность и покажет, сколько людей и записей внутри. Если написано «Копия цела»,
из неё можно восстановить. Проверять копию стоит раз в месяц: копия, которую ни разу не открывали, может оказаться негодной.

## 2. Восстановить на Railway (пропал том или база пустая)

1. В Railway у сервиса `ai_habit` убедись, что том подключён и путь монтирования `/data`
   (переменная `RAILWAY_VOLUME_MOUNT_PATH` выставляется сама).
2. Останови бота: сервис `ai_habit` → Deployments → у активного деплоя меню → Remove (или временно `Settings` →
   остановить). Пока работают два процесса с одним `BOT_TOKEN`, они мешают друг другу.
3. Загрузи файл копии на том и выполни в консоли сервиса (Railway → `ai_habit` → Console):

```bash
python backups/restore.py /data/копия.db.gz --to /data/users.db
```

   Если база по этому адресу уже лежит, скрипт откажется: добавь `--force`, и старая сохранится рядом как
   `users.db.before-restore-…`.
4. Запусти деплой заново и проверь `/health` (должно быть `{"status": "ok", "db": "ok"}`), потом открой бота.

## 3. Поднять на новом сервере (переезд или запасной вариант)

Нужен сервер с Docker. Код берётся из GitHub, настройки (`.env`) создаёшь сам.

```bash
git clone https://github.com/Githabsila/ai_habit.git adam
cd adam
docker build -f deploy/Dockerfile -t adam .
```

В файле `.env` рядом должны быть имена (значения вписываешь сам, в репозиторий этот файл не попадает):

```
BOT_TOKEN=
OPENAI_API_KEY=
GROQ_API_KEY=
ADMIN_ID=
WEBAPP_URL=https://адрес-приложения
```

Остальные настройки (цены, `CLOSED_CHANNEL_ID`, `SUBSCRIPTION_GATE_ENABLED` и другие) смотри в переменных Railway.
Сначала восстанови базу в том `adam-data`, потом запусти:

```bash
docker run --rm -v adam-data:/data -v "$PWD":/in adam python backups/restore.py /in/копия.db.gz --to /data/users.db
docker run -d --name adam --restart unless-stopped -p 8080:8080 -v adam-data:/data --env-file .env adam
```

Дальше нужен домен с HTTPS (Caddy или Nginx перед портом 8080) и прописанный в `WEBAPP_URL` адрес. Когда новый сервер
заработал, **старый нужно остановить**: бот использует long polling, два экземпляра с одним токеном дерутся за сообщения.

## 4. Проверка после восстановления

- `https://адрес/health` отвечает `ok`.
- Бот отвечает на `/start`, приложение открывается из меню, привычки и серии на месте.
- В админке видно число людей, как в проверке копии.
- После восстановления бот сам сделает свежую копию и пришлёт её в Telegram.

## 5. Если что-то пошло не так

- «не прошла проверку целостности»: возьми предыдущую копию (в Telegram их много) и повтори.
- «нет таблицы users»: это не та база; проверь, что файл пришёл от бота ADAM.
- Бот молчит после смены токена: в логах Railway будет `Unauthorized`. Значит, в `BOT_TOKEN` лежит не тот токен.
